## 实机发现并修复的差异

UiAutomator 的 XML dump 将非 BMP emoji 替换为两个点，例如“蓝牙设置🐻”变成“蓝牙设置..”。如果使用 XML 字段做追加，会损坏草稿；用它做精确验收也会误报。现改用原生 getText 读取追加前文本和输入后内容，保留树查询对焦点、包名、resource ID 和密码属性的检查。另将原生 getText 对空字段返回的 null 规范化为空字符串。两种差异均有实机结果与回归测试。

视频采用全范围 yuvj420p、单线程 MJPEG 编码及低延迟时间戳选帧，避免部分输入色彩范围被 MJPEG 拒绝和 fps 滤镜等待后续帧的问题。ADB exec-out 与 shell 的参数处理不同，设备视频包装脚本按 exec-out 参数原样传递，避免将整段脚本误当成一个被引用的可执行文件名。

### 真机：最终版本完整验收

`scripts/accept_device.py` 构建无额外权限的原生临时 App，通过官方 MCP 客户端连接真实 stdio 服务。App 使用 Android 原生长按回调、GestureDetector 双击回调和实际触摸轨迹更新计数，不以工具返回 `ok` 代替手势验收。在最终代码（提交 `d58cfcc`）上，同一轮完整通过以下 11 个场景：

1. 点击后等待 450ms 延迟显示的目标，并返回观察。
2. 点击后等待目标消失，确认 `condition_met=true, found=false`。
3. 长按触发 `LONG_PRESSES=1`。
4. 双击触发 `DOUBLE_TAPS=1`。
5. 明确起终点拖拽触发 `DRAGS=1`。
6. 自动滚动 5 次找到原本在屏外的 `Row 12`。
7. 再次查找同一可见目标，实际滑动次数为 0。
8. 滚动到最后一行后查找不存在的目标，连续两次无进展即停止。
9. 长按 / 双击与后置等待在同一批处理中完成，事件计数各增加一次。
10. 长按后的条件等待超时，长按计数仅增加一次，后续双击没有执行，批处理返回 `postcondition_timeout`。
11. 不存在目标的等待进行中调用暂停，等待以 `user_takeover` 中止，再恢复控制。

这轮核心功能验收 64.08 秒，不含 APK 构建安装与清理，不能当作其他 App 或连接环境的性能承诺。真实 MCP 工具数量为 22；查找屏外目标完成 5 次滑动，无进展保护在 2 次滑动后触发。脚本同时断言临时 App 已卸载、原前台应用已恢复；没有改变系统设置或用户 App 数据。

### 真机：额外的只读边界验证
