# Android Use v0.4.0

**Your agent. Now on Android.** Agent plans. Jev decides. Android Use acts.

[English guide](https://github.com/JackCaow/android-use/blob/v0.4.0/docs/guide.md) · [中文指南](https://github.com/JackCaow/android-use/blob/v0.4.0/docs/guide.zh-CN.md) · [Jev setup](https://github.com/JackCaow/android-use/blob/v0.4.0/docs/jev.md) · [Validation](https://github.com/JackCaow/android-use/blob/v0.4.0/docs/validation.md)

## What's new

- **Optional Agent + Jev execution.** The Agent plans, composes text and verifies outcomes; Jev chooses the next code-owned candidate; Android Use checks current UI/scope and executes once. New `aua_execute_goal` supports bounded subgoals and explicit completion or handoff. All existing MCP tools remain available: **23 tools** in total.
- **Jev setup in the live screen.** Click the gear, enter a TypeSafe API Key, and choose **验证并启用** (Verify & enable). The server checks the connection and saves the key locally. New tasks pick up changes without restarting. Test, disable and remove the saved key in the same panel. Environment-based setup still works; Jev stays off by default.
- **A phone frame for the live view.** Theme-aware bezel, side buttons, rounded screen and responsive portrait/landscape layout. Input coordinates map to the inner screen, with frame clicks excluded.
- **Less repeated work.** Device metadata is sampled once per validation phase, with fresh checks across decisions and actions. A stable input field can offer focus → exact text → native readback as one Jev candidate. Partial or uncertain actions are recorded and never automatically replayed.
- **A clearer project introduction.** New Agent / Jev / Android Use hero, English-first README with Chinese navigation, refreshed light/dark screenshots, settings screenshot and shorter onboarding.

Known paths should still use ordinary tools, batch or bounded scrolling. Jev is experimental and does not guarantee faster execution on every task. [Paired measurements, methods and retained failures](https://github.com/JackCaow/android-use/blob/v0.4.0/docs/benchmarks/optimizations-v4.md).

## Download and install

| Asset | Purpose |
| --- | --- |
| `android-use-0.4.0-plugin.zip` | Complete local plugin marketplace, source, lockfile, compiled UI, skill and bilingual docs. **Not an Android APK.** |
| `SHA256SUMS` | SHA-256 checksum for the plugin ZIP. |

Install [uv](https://docs.astral.sh/uv/getting-started/installation/), [ADB](https://developer.android.com/tools/releases/platform-tools), [ffmpeg](https://ffmpeg.org/download.html), and your MCP client first. The Codex plugin also needs the Codex CLI. These tools are not bundled. Normal use needs no Node.js, JDK, full Android SDK, root, Appium or keyboard APK. First setup needs network access.

```bash
curl -fLO https://github.com/JackCaow/android-use/releases/download/v0.4.0/android-use-0.4.0-plugin.zip
curl -fLO https://github.com/JackCaow/android-use/releases/download/v0.4.0/SHA256SUMS
# macOS; on Linux use: sha256sum -c SHA256SUMS
shasum -a 256 -c SHA256SUMS
unzip android-use-0.4.0-plugin.zip -d android-use-v0.4.0
cd android-use-v0.4.0
uv sync --frozen --python 3.13
codex plugin marketplace add .
codex plugin add android-use@android-use-release
```

Windows users can extract the ZIP using an archive tool, then run the uv/Codex commands in that directory. Keep the extracted directory as the registered marketplace source. Reload tools or open a new chat, enable Android Use and check that `aua_*` tools are available. If a desktop client cannot find uv/ADB/ffmpeg, configure absolute executable paths as described in [troubleshooting](https://github.com/JackCaow/android-use/blob/v0.4.0/docs/guide.md#troubleshooting).

**Existing installation:** update your original marketplace source and reinstall from it; avoid enabling a second copy. Source-checkout users run `git pull`, `uv sync --frozen`, `uv run python scripts/package.py`, then `codex plugin add android-use@android-use-local`. Preserve any local executable-path/environment overrides. [Full update instructions](https://github.com/JackCaow/android-use/blob/v0.4.0/docs/guide.md#updating).

### Connect Android and enable Jev

Enable USB debugging, approve the computer, and keep the intended device awake/unlocked. With multiple transports, select it explicitly.

```bash
adb devices -l
uv run android-use setup '{"action":"status"}'
# Start only if the control service is absent:
uv run android-use setup '{"action":"start"}'
uv run android-use ready
uv run android-use screen
```

Require **`ready=true`**. Open the screen URL (or ask the Agent for the embedded screen), click the gear and enter the TypeSafe key there. The connection test sends a fixed synthetic prompt, not phone UI. Enabling real Jev tasks sends the subgoal, visible UI text and supplied input values to TypeSafe. The local key file is written atomically with POSIX permissions `0600`; the server never returns it to the UI. Removing a saved key leaves Jev disabled even when an environment key exists.

### Other MCP clients

This remains **standard local stdio MCP**. Codex registration is optional. After extracting and syncing, merge into an existing `mcpServers` configuration:

```json
{
  "mcpServers": {
    "android_use": {
      "command": "uv",
      "args": ["run", "--frozen", "--directory", "/absolute/path/android-use-v0.4.0", "android-use-mcp"]
    }
  }
}
```

Cursor also uses `"type": "stdio"`; VS Code uses top-level `servers`. [Complete client examples](https://github.com/JackCaow/android-use/blob/v0.4.0/docs/guide.md#other-mcp-clients). Clients without MCP Apps can use the local browser screen, including Jev settings. The private video URL is not a remote MCP endpoint.

## Validation and limitations

- **175 Python tests**, **12 browser tests**, lint and package builds.
- Real stdio MCP emulator acceptance covers gestures, waits, scrolling, pause/resume, Unicode input, Jev completion/handoff, input macros and rotation. First-time UI key setup is checked separately with a real TypeSafe request and a goal in the same MCP session.
- Development comparisons include 18 optimization trials and 12 live Agent / Agent + Jev trials. Both live arms completed 6/6. Those synthetic samples are not a general speed or success-rate guarantee.
- Earlier physical-device acceptance covers Android 16 / Xiaomi 15 Ultra. This release's new settings/frame acceptance uses local Chrome and an Android emulator. It does not establish native desktop-host tool loading, other manufacturers or Windows/Linux end-to-end support.

Authentication remains with the user. Multi-touch, arbitrary gesture paths, fine-grained text selection and custom-editor fallbacks are not implemented. Browser/embedded-host clipboard permissions still apply to PNG copying. A selector match proves that UI condition; the Agent verifies the business outcome.
