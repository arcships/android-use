# Android Use v0.5.2

**Reconnect reliably. Know when the picture is live.**

[English guide](https://github.com/JackCaow/android-use/blob/v0.5.2/docs/guide.md) · [中文指南](https://github.com/JackCaow/android-use/blob/v0.5.2/docs/guide.zh-CN.md) · [Recovery design and validation](https://github.com/JackCaow/android-use/blob/v0.5.2/docs/preview-reconnection.md)

## What's changed

- **Fix the expired preview address.** v0.5.1 closed its HTTP listener after ten minutes without a viewer and deleted endpoint metadata. The browser kept retrying that dead address even with a healthy connected phone. The token-protected local listener now remains available; recording still stops after the five-second viewer lease.
- **Recover service restarts.** Preserve the private port/token across normal restarts and upgrades where available, briefly wait for the previous listener to release its port, and recover a failed MCP App frame read once. Phone actions are never automatically replayed; uncertain write outcomes remain explicit.
- **Confirm reconnection with fresh video.** Refresh shows “正在重连…” and only reports success after a new decoded frame with reliable geometry arrives. An HTTP OK or stale cached frame cannot produce a success notice. Persistent transport failures explain when the Agent needs to reopen the screen.
- **Simplify the Jev entry.** Replace the settings gear with an outlined sparkle and visible **Jev** label. Enabled Jev is green; the existing key configuration flow stays available.
- **Keep standard MCP and optional Jev.** All 24 existing MCP tools remain. No new runtime dependency or phone APK is required for ordinary preview.

## Validation and limits

- **305 Python tests, 21 browser tests**, Ruff, UI compilation and PR CI passed. Regression covers the former idle-expiry condition, endpoint reuse, safe read retry, no action replay, fresh-frame confirmation, and existing authorization/geometry guards.
- **Android 16 physical acceptance:** terminate only the authenticated preview daemon, recover through an MCP App read, retain the URL and receive a new video stream. The recovery read took **5.419 seconds**, after a separate 0.7-second fault-settling delay. No phone UI/business action was performed; capture processes restarted.
- Actual browser Refresh went from buffering/“正在重连…” to Live. The updated Jev entry opened its settings successfully.
- Idle-expiry regression uses an already-expired activity timestamp, not a ten-minute wall-clock soak. Standalone browsers cannot launch a missing OS process: after a reboot/manual termination, an MCP App read or Agent opening the preview is required. A permanently occupied saved port can require reopening the page.
- The earlier v0.5.1 emulator motion gap remains unresolved. This patch does not promise zero motion pauses on every device or host. Publishing does not itself update an installed or running plugin.

## Download and install

`android-use-0.5.2-plugin.zip` contains the local plugin marketplace, Python source and lockfile, compiled screen, OCR helper, skill and bilingual docs. It is **not an Android APK**. `SHA256SUMS` contains its SHA-256 checksum.

Prepare **uv, ADB and ffmpeg**. The Codex plugin additionally needs the Codex CLI; optional built-in OCR requires macOS and Xcode Command Line Tools. First installation downloads Python dependencies.

```bash
curl -fLO https://github.com/JackCaow/android-use/releases/download/v0.5.2/android-use-0.5.2-plugin.zip
curl -fLO https://github.com/JackCaow/android-use/releases/download/v0.5.2/SHA256SUMS
# macOS; Linux: sha256sum -c SHA256SUMS
shasum -a 256 -c SHA256SUMS
unzip android-use-0.5.2-plugin.zip -d android-use-v0.5.2
cd android-use-v0.5.2
uv sync --frozen --python 3.13
codex plugin marketplace add .
codex plugin add android-use@android-use-release
```

Keep the extracted directory as the marketplace source. Existing users should update their original marketplace and preserve environment-file paths, saved Jev settings and other MCP servers; avoid enabling duplicate copies. Reload the MCP process after updating, then reopen preview so its authenticated daemon upgrades. The new recovery behavior needs the updated UI and server code.

### Other MCP clients

Android Use is **standard local stdio MCP**. Codex registration is optional. Merge this entry with your client's existing configuration:

```json
{
  "mcpServers": {
    "android_use": {
      "command": "uv",
      "args": ["run", "--frozen", "--directory", "/absolute/path/android-use-v0.5.2", "android-use-mcp"]
    }
  }
}
```

Cursor also uses `"type": "stdio"`; VS Code uses top-level `servers`. [Client examples](https://github.com/JackCaow/android-use/blob/v0.5.2/docs/guide.md#other-mcp-clients). The local preview URL is not a remote MCP endpoint.

Connect an ADB-authorized, unlocked device. Ask the Agent to check `aua_setup(action="status")`, start the service once only if absent, then verify `aua_ready` returns `ready=true`. Original tools need no API key. Enable optional Jev through the screen's **Jev** button using your own TypeSafe key; keep credentials out of chat and Git.
