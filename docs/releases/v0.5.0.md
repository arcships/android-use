# Android Use v0.5.0

**Read the page you have. Act once. Verify the result.**

## What's new

- **Page-based, read-only automatic OCR.** New standard MCP tool `aua_read_fields` judges up to 12 money/text/choice fields in one Jev request. `source=auto` uses sufficient accessibility text first; missing text or expected labels triggers local macOS Vision OCR of the current ROI. `tree` disables OCR and `screen_ocr` forces it. No automatic visual clicking. All previous tools remain: **24 MCP tools** in total.
- **Fresh, traceable evidence.** Device-owned OCR records source, ROI, boxes, masks and capture metadata. Pixels outside explicit masks must match after inference. Context, pause, lock and detectable authentication are checked again. Caller-supplied text remains explicitly unverified.
- **Safer Jev actions.** Compact semantic context and parallel operation/target heads use one request. After an acknowledged mutation, bounded observation waits for an effect without another write. Transient empty trees and geometry-only animation do not count as effects. Unresolved effects or a previously consumed state/action hand back to the Agent.
- **Money parsing that preserves meaning.** Keep printed Unicode minus signs and thousands grouping, parse with Decimal, and require consistent resolved currencies for sum checks. Negative discounts go in `add`; `subtract` accepts positive magnitudes only.
- **Automatic preview recovery.** Normal encoder renewal and transient frame-request failures show recovery rather than an immediate request to reconnect manually. Reopening the screen upgrades an older authenticated preview daemon. A stream rollover requires a new decoded frame before Live resumes. Persistent failures remain visible, and pause/disconnection still clear the image and disable controls.
- **Updated English/Chinese docs.** Routing, platform requirements, compatibility changes and retained physical-acceptance failures are documented.

## Download and install

| Asset | Purpose |
| --- | --- |
| `android-use-0.5.0-plugin.zip` | Complete local plugin marketplace, source, lockfile, compiled screen, OCR helper, skill and bilingual docs. Not an Android APK. |
| `SHA256SUMS` | SHA-256 checksum for the plugin ZIP. |

Prepare **uv, ADB and ffmpeg** plus your MCP client; the Codex plugin also needs the Codex CLI. Built-in OCR additionally needs **macOS and Xcode Command Line Tools** (`xcode-select --install` if missing). OCR dependencies are not installed automatically. Linux/Windows retain AX and original tools, with a structured `ocr_unavailable` handoff when OCR is requested. First installation needs network access.

```bash
curl -fLO https://github.com/JackCaow/android-use/releases/download/v0.5.0/android-use-0.5.0-plugin.zip
curl -fLO https://github.com/JackCaow/android-use/releases/download/v0.5.0/SHA256SUMS
# macOS; on Linux use: sha256sum -c SHA256SUMS
shasum -a 256 -c SHA256SUMS
unzip android-use-0.5.0-plugin.zip -d android-use-v0.5.0
cd android-use-v0.5.0
uv sync --frozen --python 3.13
codex plugin marketplace add .
codex plugin add android-use@android-use-release
```

Keep the extracted directory as the marketplace source. Existing users should update their original marketplace, preserve local paths/settings, and avoid enabling duplicate servers. Reload MCP tools or open a new chat after updating; check that `aua_read_fields` appears. No phone app installation or root is required for ordinary control. No API key is needed for original tools; Jev remains opt-in.

### Other MCP clients

This is **standard local stdio MCP**. Codex registration is optional. After extracting and syncing, merge this entry into the client's existing configuration:

```json
{
  "mcpServers": {
    "android_use": {
      "command": "uv",
      "args": ["run", "--frozen", "--directory", "/absolute/path/android-use-v0.5.0", "android-use-mcp"]
    }
  }
}
```

Cursor also uses `"type": "stdio"`; VS Code uses top-level `servers`. [Full examples](https://github.com/JackCaow/android-use/blob/v0.5.0/docs/guide.md#other-mcp-clients). Clients without MCP Apps can open the local browser view. The preview URL is not a remote MCP endpoint.

### Enable Jev and connect Android

Enable USB debugging, approve the computer and keep the selected device unlocked. Ask the Agent to check `aua_setup(action="status")`, start the service once only if absent, then require `aua_ready` with `ready=true`. Open the live screen, click the gear, and enter your TypeSafe key yourself to **验证并启用** (Verify & enable). Settings apply to new tasks without restarting. Never put keys into chat or commit them.

OCR images stay local; recognized text and field questions are sent to TypeSafe for Jev judgments. Use a narrow ROI to exclude unrelated private data. Authentication remains with the user; the Agent independently verifies business outcomes.

## Compatibility and limits

- For `sum_check`, declare `currency` when symbols such as `¥` or `$` are ambiguous. All operands need one resolved currency. Supported declarations: CNY, JPY, USD, HKD, EUR, GBP, CAD and AUD.
- Money parsing supports comma thousands and dot decimals, including fullwidth equivalents, not every locale format. Negative `subtract` operands are rejected to avoid accidental double-negation.
- Caller `evidence_text` cannot also claim a device `source`, `region` or `ocr_masks`. It returns `freshness=unchecked`; only device-captured OCR can return checked ROI provenance.
- OCR scores are uncalibrated telemetry by default. An optional threshold gates money/text candidates; it is not a correctness probability. OCR does not establish strikethrough styling or all custom overlays. `verified=false` still requires Agent verification, even if sums match.
- Automatic visual grounding/clicking, multi-touch, arbitrary gesture paths and custom-editor input fallback remain unimplemented. Image clipboard permissions still depend on the browser/host.

## Validation

- **277 Python tests**, **17 UI tests**, Ruff, source/wheel/plugin builds, archive privacy checks and standard stdio MCP schema checks.
- Actual local macOS Vision recognized synthetic grouped and negative amounts.
- During development physical acceptance, Meituan AX/OCR both yielded **19 + 1.5 + 2.4 = 22.9 CNY**; Taobao's empty AX text automatically routed to device OCR and yielded **24 + 1.5 + 2.3 − 6 = 21.8 CNY**. The Agent independently inspected both bills and confirmed empty temporary carts. No order, payment or new coupon/card purchase occurred.
- Failed ROI, animation, low-score and missing-field attempts are retained. Different drinks and iterative development do not establish a cheapest-price ranking, matched speed improvement or production success rate.
- Later transient-empty-tree and expanded authentication guards have offline coverage only; final phone revalidation and the full video-rollover check were not completed. Other manufacturers/hosts/platform OCR providers are not covered by these results.
