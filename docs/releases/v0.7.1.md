# Android Use v0.7.1

**A steadier live screen. Now a Claude Code plugin.**

The live phone view no longer restarts its video every time the panel is briefly hidden, an authentication pause can be ended from the panel, and the repository now loads directly as a Claude Code plugin. All 26 MCP tools, keyless host decisions, optional Jev and the existing Dim / Codex integrations are unchanged.

[English README](https://github.com/arcships/android-use/blob/v0.7.1/README.md) · [中文 README](https://github.com/arcships/android-use/blob/v0.7.1/README.zh-CN.md) · [Native installation and rollback](https://github.com/arcships/android-use/blob/v0.7.1/docs/standalone.md) · [Source upgrades](https://github.com/arcships/android-use/blob/v0.7.1/docs/upgrading.md)

## What's changed

- **The encoder lingers for 30 seconds after the viewer is hidden.** Previously capture stopped 5 seconds after the last frame request, so switching away from the panel and back cost a full encoder restart, about 3 seconds of "waiting for a new picture" on the test phone. Frames stop being served as soon as the viewer is hidden, a hidden viewer never starts an encoder, and an authentication pause or a locked phone still stops capture at once.
- **Stopping video no longer blocks frame requests.** Phone-side recorder cleanup runs outside the preview lock. It used to hold that lock for up to several seconds, stalling every open panel.
- **One failed lock-state read is not a disconnect.** The stream now stops only after three consecutive failures. Tap and swipe are disabled from the first failure until the state is known again.
- **Resume from the panel.** During an authentication pause the panel shows **我已完成，恢复预览**. It clears the same shared flag as `aua_resume`, so a pause left behind by a closed agent session no longer strands every preview. A locked phone still resumes only after it is unlocked on the device.
- **Claude Code plugin.** `.claude-plugin/` adds a plugin manifest and a marketplace entry. The manifest's own MCP entry uses `${CLAUDE_PLUGIN_ROOT}`; the existing `.mcp.json` for Codex and Dim is unchanged. `/android-use:screen` opens the live screen in a local browser, because the Claude Code terminal cannot embed it. The plugin ZIP includes the manifest and the release check now covers its version.

Preview daemons from earlier versions are replaced automatically, keeping the same local address, the first time the screen is opened after updating.

## Install in Claude Code

Requires `uv`, ADB and ffmpeg on the computer the phone is connected to.

```text
/plugin marketplace add arcships/android-use
/plugin install android-use@arcships
```

The first start creates the Python environment with `uv` and needs network access. To load a source checkout or the extracted `android-use-0.7.1-plugin.zip` instead, start Claude Code with `claude --plugin-dir /absolute/path/android-use`.

Dim Agent, Codex and other MCP clients install as in [v0.7.0](https://github.com/arcships/android-use/blob/v0.7.1/docs/releases/v0.7.0.md); asset names are the same with the new version number.

## Validation and scope

- **487 Python tests and 25 browser tests** are in the suite, with Ruff and the UI build. Seven of them are new and cover the lingering encoder, lock-free stop, the lock-probe threshold and panel resume.
- The preview changes were exercised on one physical phone (Android 16, HyperOS 3, USB): returning to a hidden viewer inside the linger window served a frame immediately without a second encoder start, and no recorder process was left on the phone afterwards.
- The Claude Code plugin passed `claude plugin validate` and connected its MCP server when loaded with `--plugin-dir` on macOS with Claude Code 2.1.321. Installation from the hosted marketplace and Windows / Linux hosts have not been exercised.
- Native install, upgrade and rollback acceptance was last run for v0.7.0 and has not been repeated for this version before tagging; the release pipeline re-runs its package checks on the v0.7.1 artifacts.
- While the encoder lingers, the phone keeps recording for up to 30 seconds after the panel is hidden. Frames stay in memory only and are not written to disk.

- **面板隐藏后录屏保留 30 秒。** 此前停止取帧 5 秒就会停流，切走再切回要重新起流，测试机上约 3 秒看不到新画面。现在隐藏后立即停止提供画面，隐藏期间不会新启动录屏；认证暂停或手机锁屏仍会立刻停流。
